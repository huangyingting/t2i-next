# Copilot SDK 模型响应速度 Benchmark

测试时间：2026-09-18（UTC+8）

## 目的

本测试比较当前账号通过 Copilot SDK 实际可用模型的响应速度，并为本仓库中
Theme、Frame 和其他长文本生成任务选择默认模型提供依据。结果只衡量延迟和稳定性，
不代表生成质量排名。

## 环境与方法

- SDK：`github-copilot-sdk 1.0.14`
- 模型来源：当前账号实时调用 `CopilotClient.list_models()`
- 短任务：14 个模型入口，每个执行 3 次固定 60 英文词请求
- 长任务：短任务前六名，每个执行 3 次固定 300 英文词请求
- 调用方式：串行执行，每轮随机模型顺序，避免并发资源竞争
- Session：无工具、无仓库指令、关闭自定义指令发现
- Reasoning：SDK 默认 `reasoning_effort=medium`
- TTFT：从发送请求到第一个流式正文 delta
- 总耗时：从发送请求到 session idle
- 成功率：短任务 42/42，长任务 18/18

不同模型报告的 output token 可能包含不同规模的隐藏推理 token，因此不使用
token/s 决定排名。

## Gemini 可用性探测

`CopilotClient.list_models()` 没有返回 Gemini。为确认是否存在未枚举但可直接调用的
版本，分别尝试以下模型 ID：

| 请求的模型 ID | 会话结果 | `AssistantUsageData.model` |
|---|---|---|
| `gemini-3.5-flash` | 成功返回 | `gpt-5.6-sol` |
| `gemini-3.6-flash` | 成功返回 | `gpt-5.6-sol` |
| `gemini-3.7-flash` | 成功返回 | `gpt-5.6-sol` |
| `gemini-3.8-flash` | 成功返回 | `gpt-5.6-sol` |

这些未识别的模型 ID 被静默回退到 `gpt-5.6-sol`，不代表 Gemini 可用。SDK 本地包
和官方 `github/copilot-sdk` 仓库中也没有找到 Gemini 模型定义，因此没有把这些响应
作为 Gemini 性能结果。

要 benchmark 真实 Gemini，需要配置 Google Gemini 或其他明确返回 Gemini 模型
元数据的 provider，不能只向当前 Copilot SDK 传入 Gemini 字符串。

## 选择建议

### 短回复

优先使用 `gpt-5.6-luna`。它在 60 词任务中的中位总耗时为 6.252 秒，适合分类、
简短抽取和短问答。

### 长文本与批量 Prompt

若只考虑速度与稳定性，优先使用 `gpt-5.3-codex`。它在 300 词任务中中位总耗时
为 16.495 秒，三次最慢也只有 16.933 秒。

若优先考虑首 token，可使用 `gpt-5.6-sol-fast`。其长任务中位 TTFT 为
14.936 秒，但完整响应比 `gpt-5.3-codex` 慢约 2.806 秒。

### Auto

不建议仅为了速度使用 `auto`。本次三次请求都路由到 `mai-code-1.1-flash`，
短任务中位总耗时为 12.593 秒，明显慢于直接指定排名靠前的模型。

## Film pipeline 实测补充

速度排名不等于任务适配度：

- `gpt-5.3-codex` 和 `gpt-5.6-luna` 都能完成 Profile、Theme、Frame checkpoint
  和发布链路。
- 在 hardcore 请求且 Frame 语义验证关闭时，两者都把 Frame 降级为普通身体接触，
  离线检查均为 0/3 达到明确内容下限。
- `gpt-5.3-codex` 开启 Frame 验证后，连续三次返回标签外正文并耗尽重试。

因此模型选择应同时考虑延迟、格式遵从和内容级别遵从，不能只采用速度排名。

## 限制

- 每个条件只有 3 次样本，适合当前时段的实用比较，不是长期 SLA。
- 结果受账号区域、服务负载、配额和测试时间影响。
- 改变 reasoning effort 后，延迟和排名可能变化。
- 300 词复测只覆盖短任务前六名。
- Film pipeline 实测只覆盖单个导演、作品和请求，不代表全部任务。
- 模型列表和账号策略会变化，应定期重新运行。
